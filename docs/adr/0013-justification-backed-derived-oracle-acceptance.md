# Justification-backed derived oracle acceptance for the OWL2Bench query lane

Status: accepted

A derived oracle for an OWL2Bench query/profile case is accepted only when
four artifacts exist and pass audit. First, a deterministic derivation
procedure documented against the pinned correctness-anchor dataset (official
generator revision, seed 1, one university). Second, per-row justification
evidence: every proposed answer row carries a checkable entailment
justification (a proof trace or rule-derivation chain) relative to the
profile's declared semantics. Third, exact identity binding per ADR 0007:
source corpus, revision, query id, profile, dataset id, and canonicalizer
identity. Fourth, an independent audit: a verification session with no access
to the producing session's conclusions re-derives or verifies the
justifications; unresolved disagreements leave the case oracle_unavailable.

An engine may propose candidate answer rows, and any engine's output may be
fed to the justification step, but engine output and engine agreement confer
no authority. The engine is a proposer, not a certifier. This operationalizes
the second rung of the ADR 0007 authority ladder without weakening it.

Acceptance is piloted on the RL profile (18 cases) before any other profile.
A profile extension happens only after the pilot audit closes with no
unrecoverable evidence gap. An outbound request to the OWL2Bench authors for
official or endorsed expected results, or for an external audit, was drafted
but the maintainer decided not to send it (2026-09-26): independent
artifact-level search already established that no public answer key exists,
so the request's remaining value is a possible authority upgrade only. The
derived path proceeds without it; contact can be reopened later (for example
before publication) without changing this procedure.

## Considered Options

- Full manual pen-and-paper derivation of all 60 cases was rejected because
  the manual cost is unbounded and hand-derivation errors would themselves
  need an audit of comparable rigor.
- Engine agreement as the oracle was rejected by ADR 0007: correlated
  implementations do not establish semantic correctness.
- Audit by the same session that produced the derivation was rejected as
  self-certification, which the result contract forbids.

## Consequences

A case's status can only move off oracle_unavailable when its derived oracle
is accepted under this procedure, after which wrong and passed become
reachable. Execution evidence, timing fields, and the konclude-unified
results are unchanged and remain differential. The justification artifacts
and the audit report are committed as evidence so the acceptance is
replayable. The audit trail must not be generated by the implementation
under test.
