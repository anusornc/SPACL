# Seed-generated RL correctness anchor replaces the staged sample

Status: accepted

The RL correctness anchor for the OWL2Bench derived-oracle pilot is the
dataset generated by the official generator at the paper-reported
configuration: `kracr/owl2bench` revision
`5a27536c8e7f7621b34c61c8a57ed9eb63e7829a`, `java -jar OWL2Bench.jar 1 RL 1`
(one university, RL profile, seed 1), staged as
`staged/0005_UNIV-BENCH-OWL2RL-seed1-u1.owl` (50,839 axioms). Generation is
byte-deterministic: two runs produce sha256
`78d7a0780e8cf7bf5d375d2a13b30c6bad8fa5c0763854770c6ae7f6fb9104f3`. Generator
inputs are pinned in the staged manifest row.

This aligns the anchor with ADR 0007's own definition (official generator
revision, seed 1, one university). The previously frozen staged sample
(`staged/0004_UNIV-BENCH-OWL2RL.owl`) is TBox-dominant — about eleven
non-TBox property assertions in total — so deriving an oracle over it
certifies an empty answer set for 17 of 18 RL cases and risks a vacuously
passing RL gate: engines that also return nothing would be marked passed
without the gate having tested any semantic content. The 0004 sample remains
staged as pipeline-validation evidence, not as the correctness anchor.

## Considered Options

- Keeping the staged sample was rejected because an oracle over it would
  certify emptiness and could let the RL gate pass vacuously, which is a
  correctness claim the evidence cannot support.
- Waiting for the OWL2Bench authors to publish an official key was rejected
  as the anchor decision: the outbound request remains open, but the campaign
  should not block on it when the policy-defined anchor is reproducible
  today.

## Consequences

Derived-oracle derivations for RL run against the 0005 anchor; case identity
carries the new dataset id and sha256. Closure and justification artifacts
grow by roughly two orders of magnitude, and derivation cost becomes a
recorded part of the evidence. If the authors later publish official
expected results, the authority ladder still prefers them unchanged.
